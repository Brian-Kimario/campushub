# CampusHub — Data Model

**Purpose:** Authoritative relational schema: tables, keys, constraints, indexes, and invariants enforced by the database.
**Scope:** MySQL 8 schema targeted by Flyway migrations V1–V8 (Phase 1–7). P2 tables are listed but not migrated until Phase 8.
**Last reviewed:** 2026-11-03 (Phase 0)
**Related:** [ERD.md](ERD.md) (diagram), [STATE_MACHINES.md](STATE_MACHINES.md) (status values), [API_CONTRACT.md](API_CONTRACT.md).

## 1. Conventions

| Topic | Rule |
|---|---|
| Primary keys | `id BINARY(16)` holding a UUIDv7 generated by the application. Exposed in APIs as the canonical 36-character string. Never sequential. |
| Timestamps | `DATETIME(6)` storing UTC. Columns: `created_at`, `updated_at`. Academic dates (`starts_on`, `ends_on`, `issued_on`) use `DATE`. |
| Enums | `VARCHAR(32)` with a `CHECK` constraint listing the allowed values. Chosen over native `ENUM` so migrations can add values without table rebuilds. |
| Optimistic locking | `version INT NOT NULL DEFAULT 0` mapped to `@Version` on `projects`, `milestones`, `tasks`. |
| Soft deactivation | `users.status` and `academic_*.active` columns. Rows referenced by history are never hard-deleted (ADR-017). |
| Text | `VARCHAR` lengths match the requirement limits; `TEXT` only for bodies (descriptions, feedback). `utf8mb4_unicode_ci`. |
| Money, floats | Not used. |
| Foreign keys | Declared on every reference with explicit `ON DELETE RESTRICT`. Cascade deletes are forbidden because they would bypass audit. |

## 3. Identity and academic catalog

### 3.1 `users`

| Column | Type | Null | Constraints and notes |
|---|---|---|---|
| `id` | BINARY(16) | no | PK |
| `email` | VARCHAR(254) | no | UNIQUE; stored lowercase |
| `institutional_id` | VARCHAR(32) | yes | UNIQUE; nullable for admin accounts |
| `password_hash` | VARCHAR(100) | no | BCrypt `$2a$12$…` or Argon2id encoded string; never returned |
| `display_name` | VARCHAR(100) | no | 1–100 characters |
| `role` | VARCHAR(32) | no | CHECK in (`STUDENT`,`FACULTY`,`ADMIN`); one role only (ADR-021) |
| `status` | VARCHAR(32) | no | CHECK in (`ACTIVE`,`DEACTIVATED`); default `ACTIVE` |
| `must_change_password` | BOOLEAN | no | default `TRUE` for admin-created accounts |
| `failed_login_count` | INT | no | default 0; reset on success |
| `locked_until` | DATETIME(6) | yes | UTC; set after 5 consecutive failures |
| `revoked_after` | DATETIME(6) | yes | UTC; set on password reset and on deactivation. Any token with `iat` before this instant is rejected (SECURITY §3). Added by V3 |
| `department_id` | BINARY(16) | yes | FK → `departments` |
| `program` | VARCHAR(120) | yes | Students |
| `cohort` | VARCHAR(20) | yes | Students, e.g. `2026` |
| `designation` | VARCHAR(120) | yes | Faculty |
| `bio` | VARCHAR(1000) | yes | Editable by owner |
| `created_at`, `updated_at` | DATETIME(6) | no | |
| `version` | INT | no | optimistic lock (not used by profile PATCH in MVP; reserved) |

Indexes: `uk_users_email`, `uk_users_institutional_id`, `ix_users_role_status (role, status)`.
Invariant: a DEACTIVATED user cannot authenticate; `revoked_tokens` is not required for this because `status` is checked per request (FR-AUTH-06).

### 3.2 `departments`

`id`, `code` VARCHAR(20) UNIQUE, `name` VARCHAR(150), `active` BOOLEAN default TRUE, timestamps. Index `ix_departments_active (active, name)`.

### 3.3 `academic_terms`

`id`, `code` VARCHAR(20) UNIQUE (e.g. `2026-S1`), `name` VARCHAR(100), `starts_on` DATE, `ends_on` DATE, `status` VARCHAR(32) CHECK in (`ACTIVE`,`INACTIVE`), timestamps.
Checks: `ends_on > starts_on`. Index `ix_terms_status_starts (status, starts_on)`.
Rule: only `ACTIVE` terms accept new projects (FR-PROJ-01).

### 3.4 `courses`

`id`, `code` VARCHAR(20) UNIQUE, `title` VARCHAR(200), `department_id` FK NOT NULL, `active` BOOLEAN default TRUE, timestamps. Index `ix_courses_department (department_id, active)`.

## 4. Authentication and audit

### 4.1 `revoked_tokens`

| Column | Type | Notes |
|---|---|---|
| `jti` | CHAR(36) | PK; access-token ID |
| `user_id` | BINARY(16) | FK → `users` |
| `expires_at` | DATETIME(6) | Token's `exp`; rows purged after this instant by a scheduled job |
| `revoked_at` | DATETIME(6) | |

Index `ix_revoked_expires (expires_at)`. Lookup happens on every authenticated request by primary key, which is cheap. Purge runs hourly (OPERATIONS §5).

### 4.2 `audit_events`

| Column | Type | Notes |
|---|---|---|
| `id` | BIGINT | AUTO_INCREMENT PK; ordering only, never exposed as a resource ID in APIs |
| `occurred_at` | DATETIME(6) | UTC, set by application clock |
| `actor_id` | BINARY(16) | nullable (anonymous login failures record `NULL` actor) |
| `action` | VARCHAR(64) | Dotted verb, e.g. `project.approved`, `auth.login_failed` |
| `target_type` | VARCHAR(40) | e.g. `PROJECT`, `SUBMISSION_VERSION` |
| `target_id` | VARCHAR(36) | Canonical string ID |
| `outcome` | VARCHAR(16) | `SUCCESS` or `DENIED` |
| `request_id` | VARCHAR(36) | Correlation ID |
| `ip_hash` | CHAR(64) | SHA-256 of client IP with a server-side salt; raw IP never stored |
| `metadata` | JSON | Sanitized; allow-listed keys only (SECURITY §8) |

Indexes: `ix_audit_occurred (occurred_at)`, `ix_audit_actor (actor_id, occurred_at)`, `ix_audit_target (target_type, target_id)`, `ix_audit_action (action, occurred_at)`.
Privileges: runtime user has `INSERT, SELECT` only (ADR-023). No code path updates or deletes audit rows.

## 5. Projects and membership

### 5.1 `projects`

| Column | Type | Null | Notes |
|---|---|---|---|
| `id` | BINARY(16) | no | PK |
| `title` | VARCHAR(200) | no | 3–200 characters |
| `description` | TEXT | yes | ≤ 5000 characters (validated in service; `CHECK (CHAR_LENGTH(description) <= 5000)`) |
| `term_id` | BINARY(16) | no | FK → `academic_terms` RESTRICT |
| `course_id` | BINARY(16) | yes | FK → `courses` RESTRICT |
| `owner_id` | BINARY(16) | no | FK → `users` RESTRICT; must hold a STUDENT role at creation |
| `supervisor_id` | BINARY(16) | yes | FK → `users`; must hold FACULTY role and be ACTIVE when set |
| `status` | VARCHAR(32) | no | CHECK in (`DRAFT`,`PROPOSED`,`REJECTED`,`APPROVED`,`ACTIVE`,`COMPLETED`,`ARCHIVED`) |
| `rejection_reason` | VARCHAR(1000) | yes | Set on rejection |
| `created_at`, `updated_at` | DATETIME(6) | no | |
| `version` | INT | no | `@Version` |

Indexes: `ix_projects_term_status (term_id, status)`, `ix_projects_supervisor_status (supervisor_id, status)`, `ix_projects_owner (owner_id)`.
Invariants:
- `status` in (`APPROVED`,`ACTIVE`,`COMPLETED`) requires `supervisor_id IS NOT NULL` (CHECK constraint).
- `status = 'REJECTED'` requires `rejection_reason IS NOT NULL`.

### 5.2 `project_members`

| Column | Type | Notes |
|---|---|---|
| `project_id` | BINARY(16) | FK → `projects` RESTRICT |
| `user_id` | BINARY(16) | FK → `users` RESTRICT |
| `membership_role` | VARCHAR(16) | CHECK in (`OWNER`,`MEMBER`) |
| `joined_at` | DATETIME(6) | |

PK `(project_id, user_id)`. Index `ix_members_user (user_id, project_id)` for "my projects" queries.
Invariants: exactly one `OWNER` row per project, enforced by a generated column `owner_key = CASE WHEN membership_role='OWNER' THEN project_id END` with `UNIQUE (owner_key)`. A member count cap (5, OD-3) is enforced in the service inside a locked project row transaction, not by the database.

### 5.3 `project_invitations`

| Column | Type | Notes |
|---|---|---|
| `id` | BINARY(16) | PK |
| `project_id` | BINARY(16) | FK RESTRICT |
| `invitee_id` | BINARY(16) | FK RESTRICT |
| `invited_by` | BINARY(16) | FK RESTRICT |
| `status` | VARCHAR(16) | CHECK in (`PENDING`,`ACCEPTED`,`DECLINED`,`EXPIRED`) |
| `expires_at` | DATETIME(6) | `created_at + 14 days` |
| `responded_at` | DATETIME(6) | nullable |
| `pending_key` | VARCHAR(80) | generated: `CASE WHEN status='PENDING' THEN CONCAT(project_id,':',invitee_id) END` |

`UNIQUE (pending_key)` allows at most one PENDING invitation per project and invitee while leaving historical rows unconstrained. Expired invitations are transitioned to `EXPIRED` lazily on read and by an hourly job.

## 6. Milestones, tasks, and activity

### 6.1 `milestones`

`id`, `project_id` FK RESTRICT, `sequence` SMALLINT, `title` VARCHAR(200), `due_at` DATETIME(6) NOT NULL, `allow_late` BOOLEAN default FALSE, `status` VARCHAR(16) CHECK in (`OPEN`,`CLOSED`), timestamps, `version`.
Unique `(project_id, sequence)`. Index `ix_milestones_project_due (project_id, due_at)` for calendar and at-risk queries.

### 6.2 `tasks`

| Column | Type | Notes |
|---|---|---|
| `id` | BINARY(16) | PK |
| `project_id` | BINARY(16) | FK RESTRICT |
| `milestone_id` | BINARY(16) | nullable FK RESTRICT; must belong to the same project (enforced in service and by a composite FK `(project_id, milestone_id)` referencing `milestones(project_id, id)` — requires a unique key on `milestones(project_id, id)`) |
| `title` | VARCHAR(200) | 3–200 |
| `description` | TEXT | ≤ 5000 |
| `status` | VARCHAR(16) | CHECK in (`TODO`,`IN_PROGRESS`,`IN_REVIEW`,`BLOCKED`,`DONE`) |
| `priority` | VARCHAR(8) | CHECK in (`LOW`,`MEDIUM`,`HIGH`) default `MEDIUM` |
| `assignee_id` | BINARY(16) | nullable FK RESTRICT; the service requires an active `project_members` row |
| `blocked_reason` | VARCHAR(500) | required when `status='BLOCKED'` (CHECK `status <> 'BLOCKED' OR blocked_reason IS NOT NULL`) |
| `due_at` | DATETIME(6) | nullable |
| `created_by` | BINARY(16) | FK RESTRICT |
| `created_at`, `updated_at`, `version` | | `@Version` |

Indexes: `ix_tasks_project_status_due (project_id, status, due_at)`, `ix_tasks_assignee_status_due (assignee_id, status, due_at)`, `ix_tasks_milestone (milestone_id)`.

**MVP deviation (`V5__tasks.sql`, IMPLEMENTATION_LOG §11).** The applied table has no `milestone_id` or `assignee_id`, so the composite milestone FK, the assignee index, and the milestone index are absent. The due column is `due_date DATE`, not `due_at DATETIME(6)`. `completed_at DATETIME(6)` is added and set only when `status='DONE'`. The migration has a single index, `ix_tasks_project_status_due (project_id, status, due_date)`. The `blocked_reason` CHECK is kept.

### 6.3 `task_comments` (P1)

`id`, `task_id` FK RESTRICT, `author_id` FK RESTRICT, `body` VARCHAR(2000) NOT NULL, `created_at`. Append-only: no UPDATE/DELETE endpoint. Index `ix_comments_task_created (task_id, created_at)`.

### 6.4 `project_activity` (P1)

`id` BIGINT PK, `project_id` FK RESTRICT, `actor_id` FK RESTRICT, `kind` VARCHAR(40), `summary` VARCHAR(300), `created_at`. Index `ix_activity_project_created (project_id, created_at)`. Written in the same transaction as the change it describes. Contains no file content and no secrets.

## 7. Submissions, files, and reviews

### 7.1 `submissions`

`id`, `project_id` FK RESTRICT, `milestone_id` FK RESTRICT, `created_by` FK RESTRICT, `current_version_no` INT, `created_at`, `version`.
`UNIQUE (milestone_id)` — one submission per milestone (FR-SUB-01). `project_id` is denormalized for scoped queries and is kept consistent by a composite FK `(project_id, milestone_id) → milestones(project_id, id)`.

### 7.2 `submission_versions`

| Column | Type | Notes |
|---|---|---|
| `id` | BINARY(16) | PK |
| `submission_id` | BINARY(16) | FK RESTRICT |
| `version_no` | INT | ≥ 1 |
| `status` | VARCHAR(20) | CHECK in (`DRAFT`,`SUBMITTED`,`UNDER_REVIEW`,`CHANGES_REQUESTED`,`ACCEPTED`) |
| `created_by` | BINARY(16) | FK RESTRICT |
| `sealed_at` | DATETIME(6) | set on submit; NULL while DRAFT |
| `sealed_by` | BINARY(16) | FK RESTRICT; NULL while DRAFT |
| `created_at` | DATETIME(6) | |

`UNIQUE (submission_id, version_no)`. Invariant: `sealed_at IS NULL` exactly when `status = 'DRAFT'` (CHECK).
Immutability: a `BEFORE UPDATE` trigger on `submission_versions` rejects changes to `version_no`, `submission_id`, `created_by`, and `sealed_at` once `sealed_at` is set, and rejects `status` regressions. The service sets status through the state machine; the trigger is the last line of defense (FR-SUB-07, ADR-018).

### 7.3 `submission_files`

| Column | Type | Notes |
|---|---|---|
| `id` | BINARY(16) | PK |
| `version_id` | BINARY(16) | FK RESTRICT |
| `original_filename` | VARCHAR(255) | sanitized: basename only, control characters removed, length-limited |
| `declared_content_type` | VARCHAR(100) | from the client; informational only |
| `detected_type` | VARCHAR(16) | CHECK in (`PDF`,`PNG`,`JPEG`,`DOCX`) from magic bytes |
| `size_bytes` | BIGINT | ≤ 20 971 520 (20 MiB) |
| `sha256` | CHAR(64) | content hash for integrity and deduplication reporting |
| `storage_key` | CHAR(36) | random UUID; `UNIQUE`; never derived from filename |
| `uploaded_by` | BINARY(16) | FK RESTRICT |
| `uploaded_at` | DATETIME(6) | |

Limits: ≤ 5 rows per `version_id` enforced in service and by a `BEFORE INSERT` trigger that counts rows. Insert and delete triggers reject any change when the parent version is not `DRAFT`.

### 7.4 `reviews`

`id`, `version_id` UNIQUE FK RESTRICT, `reviewer_id` FK RESTRICT, `decision` VARCHAR(20) CHECK in (`ACCEPTED`,`CHANGES_REQUESTED`), `feedback` TEXT NULL, `created_at`.
Invariant: `decision = 'ACCEPTED' OR feedback IS NOT NULL` (CHECK). `UNIQUE (version_id)` enforces one decision per version (FR-REV-02).

**MVP deviation (IMPLEMENTATION_LOG §11, Stage 3).** Migration `V6__submissions.sql` builds one `submissions` table with one row per revision, scoped to `project_id`, and replaces §7.1 through §7.4 for the MVP. Columns: `revision_no`, `title`, `description`, `link` (CHECK `https://%`), `status` (SUBMITTED, UNDER_REVIEW, CHANGES_REQUESTED, ACCEPTED), `submitted_by`, `submitted_at`, `reviewed_by`, `reviewed_at`, `feedback`, and `version`. The decision is stored on the same row, so `submission_versions`, `submission_files`, and `reviews` are not built. Constraints: `UNIQUE (project_id, revision_no)`; a CHECK that a review exists only in the decided and under-review states; and a CHECK that CHANGES_REQUESTED has feedback. DRAFT is not a status: a revision is sealed at creation.

## 8. Skills and certifications (P1)

- `skills`: `id`, `name` VARCHAR(80) UNIQUE after normalization (trimmed, lowercased key in `name_key`), `category` VARCHAR(60), `active` BOOLEAN.
- `user_skills`: PK `(user_id, skill_id)`, `proficiency` CHECK in (`BEGINNER`,`INTERMEDIATE`,`ADVANCED`,`EXPERT`), `evidence_note` VARCHAR(500) NULL, `updated_at`.
- `certifications`: `id`, `owner_id` FK RESTRICT, `title` VARCHAR(200), `issuer` VARCHAR(200), `issued_on` DATE, `credential_url` VARCHAR(500) NULL CHECK (`credential_url IS NULL OR credential_url LIKE 'https://%'`), `created_at`. Index `ix_certs_owner (owner_id, issued_on)`.
- `certification_files`: same columns as `submission_files` minus version link, with `certification_id` FK RESTRICT. Delete of a certification removes its file rows and storage objects in one transaction, after the database commit succeeds (see [ARCHITECTURE.md](ARCHITECTURE.md) §12).

## 9. Phase 8 tables (P2, not migrated before Phase 8)

- `outbox_events`: `id` BINARY(16), `aggregate_type`, `aggregate_id`, `event_type`, `payload` JSON, `created_at`, `published_at` NULL. Index `ix_outbox_unpublished (published_at, created_at)`.
- `processed_events`: `consumer` VARCHAR(80), `event_id` BINARY(16), `processed_at`, PK `(consumer, event_id)`.
